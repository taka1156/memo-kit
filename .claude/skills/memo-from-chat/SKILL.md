# memo-from-chat

会話 → 解説ページ → MEMO 登録、までを一続きで行う。

## 1. 題材を決める

- 「さっきの」「今の」と言われたら、直前の会話で説明した内容を題材にする。範囲が曖昧なら（複数の話題があるなど）どれにするか 1 回だけ確認する。
- テーマだけ渡された場合は、そのテーマを一から解説する。
- 1 ページ 1 テーマ。大きすぎるときは分割を提案する。
- 既存メモとの重複を確かめる: `docs/llms.txt`（全メモの目次）を読む。ほぼ同じテーマのメモがあれば、新しく作るか既存のメモに追記するかを 1 回だけ確認する。関連するメモがあれば、本文から相互にリンクしてよい。既存メモの中身を読むときは HTML ではなく Markdown 版（`docs/md/NAME.md`）を読む（memo-reference スキル）。

## 2. 中身を組み立てる

会話の文章をそのまま貼るのではなく、ページ向けに再構成する。

- 「ざっくり言うと」3 行
- 仕組み・流れ・構造 → 図（インライン SVG / CSS のボックスと矢印）
- 比較 → 表やタブ
- 手順 → 番号付きステップ
- コマンドやコード → `<pre>` ブロック
- 会話中で出た質問や誤解 → 「よくある誤解」セクション
- 確認クイズ 3〜5 問（memo-style の「確認クイズ」の作問ルールに従う。会話中でユーザーが迷った点・誤解した点は良い問題になる）

事実関係が会話の後で変わっていそうなもの（バージョン、料金、仕様）は、必要なら調べ直す。

## 3. HTML を書く

- memo-style スキルの規約を読む。
- 名前は memo-publish の規則（英小文字・ハイフン）で決め、`python3 scripts/memo.py new NAME` でテンプレートから作る。表示されたパスのファイルに書く。
- メタ情報（title / description / memo:tags / memo:date）と確認クイズも書いておく。
- ファイルとして直接保存する（チャットに貼ってからコピペさせない。崩れの原因になる）。

## 4. 登録する

memo-publish の手順 4〜8（lint → meta → build → commit/push → 報告）を実行する。
