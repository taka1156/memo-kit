# memo-roadmap

ロードマップは、書いたメモとこれから書くテーマを分野ごとに並べたチェックリスト（`src/roadmap.html`）。チェックはページが `memos.json` を見て自動で付けるので、このスキルがやるのは **項目（`ROADMAP`）を決めて書き換えること** と、**その順にメモを書くこと** だけ。ページの作り・オプションの仕組みは `memo-detail.md` の「ロードマップ（オプション）」を読む。

## 0. 使う前に

```bash
cd "$(git rev-parse --show-toplevel)"
python3 scripts/memo.py config roadmap   # True / False
python3 scripts/memo.py list            # 書いたメモ（ファイル名・タイトル・タグ）
```

- `False` なら、ロードマップを使うかをユーザーに聞く。使うなら `memo.config.json` に `"roadmap": true` を書く（ほかの項目と並び順はそのまま）。使わないなら、このスキルはここで終わり。
- 項目は `src/roadmap.html` のスクリプト冒頭の `const ROADMAP = [ ... ];` にある。読むのはそこだけでよい。

どの手順に進むかは依頼と `ROADMAP` の中身で決める。

| 状況・依頼 | 手順 |
| --- | --- |
| `ROADMAP` がキットの例のまま（`next-topic.html` がある、サンプルのメモしかない）、または「ロードマップを作って／作り直して」 | A. 計画を作る |
| 「次のメモを書いて」「次は何？」「高のを 3 本」 | B. 次のメモを書く |
| ロードマップにないメモを登録した（memo-publish から呼ばれる）、「このメモを入れて」 | C. 書いたメモを足す |
| 「見直して」「整理して」 | D. 見直す |

## 項目の書き方

```js
const ROADMAP = [
  { id: 'network', name: 'ネットワーク', note: '分野の一言（省略可）', items: [
    { file: 'tcp-ip.html' },                                   // 書いたメモは file だけ（タイトルは一覧から出る）
    { file: 'lb-proxy-cdn.html', title: 'ロードバランサと CDN の役割分担', prio: 'high',
      note: 'なぜ要るかを 1 行', alt: ['load-balancer.html'] },  // これから書くテーマ
  ]},
];
```

- **分野（`id`・`name`）は「領域」で分ける**（ネットワーク・Linux・データベース・フロントエンドなど）。理論寄りでも領域がはっきりしていればその分野に入れ、どの領域にも属さない横断的な概念（数値や文字の表現、メモリ、並行処理、データ構造など）だけを別の分野にまとめる。`memo.py list` に出ているタグがあれば分野名もそれに合わせる。
- **1 項目 = 1 本のメモ。** 粒度は memo-style の「1 本にするか分けるか」に合わせる。単独で引きたくなる話題が 2 つ以上入っている項目（「A と B」「A・B・C・D」）は分けておく。
- `file` は `memo.py new` に渡す名前＋`.html`（英小文字・数字・ハイフン。`index`・`quiz`・`settings`・`roadmap` は使えない）。既存のファイル名と重ねない。
- `prio` は `high` / `mid` / `low`。`high` はほかのメモの前提になるもの・抜けていると全体がつながらないもの、`low` はあれば便利な発展的なもの。
- `note` は「なぜ要るか」を 1 行（既存のどのメモとつながるか、など）。
- `alt` は別の名前で作っても済みにしたいときのファイル名（省略可）。
- 書いたメモは必ずどこかの項目に入れる（入っていないと「ロードマップ外のメモ」に出る）。
- 文字列は半角の `'`、最後の要素の後ろのカンマはあってよい。`</script>` を書かない。

## A. 計画を作る（最初の 1 回）

1. `memo.py list` で、もう書いたメモを確かめる。
2. ユーザーに聞く（AskUserQuestion が使えればそれで。まとめて 1 回）:
   - 何のためのメモ置き場か（学習のため・仕事の資料・あとで引く辞書 など）
   - 興味のある分野・これから触る技術
   - もう知っていて飛ばしたいこと
   - 量の目安（まず 10 本くらい、など）
3. 答えを元に案を作る。分野ごとに、書いたメモ（`file` だけ）と、これから書くテーマ（`file`・`title`・`prio`・`note`）を並べる。分野の中は「先に読むもの → 後で読むもの」の順にし、分野の全体像をたどる入口のメモが要りそうなら項目に入れる。
4. 案を表（分野・テーマ・優先度・理由）で見せ、直したいところを聞く。了承をもらってから `ROADMAP` を書き換える（キットの例は消す）。
5. 「書き換えたら」へ。

ユーザーがその場にいない（スケジュール実行など）ときは、計画は作らずに案だけ報告する（書く順番はユーザーが決めるもの）。

## B. 次のメモを書く

1. **未着手の項目を出す。** `ROADMAP` の各項目の `file` と `alt` のどれも `memo.py list` に無いものが未着手。
2. **選ぶ。** 依頼で指定があればそれ（「ネットワークの次」「高のを 3 本」など）。なければ次の順:
   - `prio` が `high` → `mid` → `low`
   - 同じ優先度なら、`ROADMAP` の分野の順・分野の中の並び順（前にあるものが先）
   - ただし、`note` やほかの項目から、先に書くべき前提（入口のメモ・土台になるテーマ）が未着手だと分かれば、そちらを先にする
3. **本数。** 指定がなければ 1 本。複数のときも 1 本ずつ、登録（memo-publish の報告）まで終えてから次へ進む。まとめて作ってから登録しない（ファクトチェックの指摘や方向の修正を次の 1 本に活かすため）。
4. **伝えてから始める。** 選んだテーマと理由を 1 行で伝える（複数なら順番の一覧）。
5. **書く。** memo-style で作り、memo-publish で登録する（手順はそれぞれのスキルに従う）。
   - 名前は項目の `file` に合わせる（`python3 scripts/memo.py new NAME` の NAME は `.html` を除いたもの）。
   - memo-style の分割の判断で分けることになったら、`ROADMAP` の項目も同じように分ける。
   - 項目と違う名前で作ったときは、その名前を項目の `alt` に足す。
6. **ロードマップを直す。** 書き終えた項目はそのままでよい（チェックは自動で付く）。書いている途中で、新しく要ると分かったテーマがあれば項目に足すことを提案する。

## C. 書いたメモを足す

memo-publish でメモを登録したあと、ロードマップがオンで、そのメモのファイル名がどの項目の `file`・`alt` にも無いとき:

1. どの分野に入れるか（無ければ新しい分野）を 1 つ提案し、了承をもらって `{ file: 'NAME.html' }` を足す。そのメモが未着手の項目と同じテーマなら、新しく足さずにその項目の `alt` に入れる。
2. ユーザーがその場にいなければ、いちばん近い分野に足して、どこに入れたかを報告する。

## D. 見直す

1. 分野ごとの済み・未着手の数、`high` の未着手、どの項目にも入っていないメモ（ロードマップ外）を数えて見せる。
2. 次を提案する（必要なものだけ）: 抜けている分野・テーマ、粒度が大きい項目の分割、優先度の入れ替え、もう書かないテーマの削除、分野の付け替え。
3. 了承をもらった分だけ書き換える。

## 書き換えたら

1. 壊れていないか確かめる。

   ```bash
   python3 scripts/memo.py preview roadmap -o <スクラッチパッド>/roadmap.html
   ```

   出力をブラウザ（Playwright など）で開けるなら、コンソールのエラーが無く、チェックの数が想定どおりかを見る。開けなければ、`ROADMAP` の部分を `node --check` に通すか、括弧・引用符・カンマの対応を読み直す。

2. commit / push する。ロードマップの項目はメモの本文ではないので、ファクトチェックは要らない。

   ```bash
   BRANCH="$(python3 scripts/memo.py config branch)"
   git fetch origin "$BRANCH"          # 遅れていれば rebase
   git add src/roadmap.html memo.config.json
   git commit -m "Update roadmap: <何を変えたか>"
   git push origin HEAD:"$BRANCH"
   ```

   B でメモを書いたときは、メモの登録（memo-publish）とは別のコミットにしてよいし、同じコミットに含めてもよい。

3. 報告する: 変えた項目（足した・分けた・消した・優先度を変えた）、全体の済み / 全部の数、次に書く候補（`high` の未着手の先頭 1〜3 件）。
