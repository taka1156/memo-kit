# memo-style

MEMO の各ページを見た目・作りの両面で揃えるための規約。
新規作成時は、リポジトリのルートで次を実行してテンプレートから作り、表示されたパスのファイルに中身を書く。

```bash
cd "$(git rev-parse --show-toplevel)"
python3 scripts/memo.py new NAME   # NAME は英小文字・ハイフン（例: git-rebase）
```

テンプレートの実体はこのフォルダの `template.html`。置き場所はスクリプトが決めるので、自分でパスを組み立ててコピーしない。

## 基本方針

- **HTML 1 枚で完結**。CSS / JS はインライン。外部は Google Fonts と、必要なら cdnjs のライブラリのみ。
- **日本語**で書く。専門用語は英語併記（例: 名前空間 (namespace)）。
- 「読む」より「見てわかる」を優先: 図（インライン SVG / CSS ボックス）、タブ切り替え、ホバーで補足、などを使う。
- スマホ幅（〜380px）で横スクロールが出ないこと。左右 16px 以上の余白。

## デザイントークン

トップページ（メモ一覧）と揃える。`:root` に変数で定義し、ダークモードは `prefers-color-scheme` で切り替え。

| 変数 | ライト | ダーク | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#f6f7f9` | `#0a0e14` | 背景 |
| `--surface` | `#ffffff` | `#111823` | カード・パネル |
| `--fg` | `#1c2230` | `#cdd9e5` | 本文 |
| `--fg-2` | `#5a6376` | `#7d8b9d` | 補足文字 |
| `--line` | `#dde1e8` | `#1e2d3d` | 罫線 |
| `--accent` | `#0077b6` ※ | `#00d4ff` ※ | 見出し・強調・リンク |
| `--chip` | `#eceff4` | `#18222f` | タグ・ボタン背景 |

※ `--accent` はサイトの設定（`memo.config.json` の `branding.accent_light`・`branding.accent`）で決まり、`build` が自動生成ブロック（`memo:head`）でページの値を上書きする。ページには表の値を書いておけばよく、色を自分で変えない。アクセント色が要る箇所は必ず `var(--accent)` を使い、色の値を直接書かない（`rgba()` で薄めたいときは `color-mix(in srgb, var(--accent) 20%, transparent)`）。

図の中で色分けが必要なときは、意味ごとに追加変数を定義する（例: `--c-ok`, `--c-warn`）。色だけで意味を伝えず、ラベルも付ける。

- 本文フォント: `'Noto Sans JP', system-ui, sans-serif`
- 見出し・コード・数値: `'JetBrains Mono', ui-monospace, monospace`
- 本文 15px 前後、行間 1.7。最大幅 880px で中央寄せ。

## ページ構成

1. `h1` タイトル（アクセント色、等幅フォント）＋ 1 行のサブタイトル
2. 要点（3 行程度の「ざっくり言うと」）
3. 本体: 図解・タブ・ステップ。セクションは `h2` で区切る
4. 必要なら「よくある誤解」「コマンド例」
5. 確認クイズ（問題データだけ書く。表示は自動。下の「確認クイズ」参照）
6. ページ下部フッターの「← 一覧に戻る」リンク（`index.html` へ。テンプレートに含まれている。固定表示のボタンにはしない）

## メタ情報（必須）

`<head>` に入れる。memo-publish の `memo.py meta` で後から付けてもよい。

```html
<title>Docker 動作原理</title>
<meta name="description" content="何がわかるページかを 1 文で">
<meta name="memo:tags" content="Docker, Linux">
<meta name="memo:date" content="YYYY-MM-DD">
```

アイコン（ファビコン・iOS）と OGP のタグは `memo.py` が `<!-- memo:head -->` ブロックとして自動で入れるので、自分では書かない。

## 確認クイズ（必須）

ページを読み流して終わらないよう、内容を使えるかを確かめる問題を **3〜5 問** つける。
ページは辞書的にも使うので、クイズは本文の最後に置く（`memo.py` が自動でページ末尾に表示する）。
全ページの問題はトップの「ランダムクイズ」と `quiz.html`（ランダム 10 問・カテゴリ別 10 問）にも出る。

書くのは問題データだけ。`</body>` の直前などに置く（テンプレートに例がある）:

```html
<script type="application/json" id="memo-quiz">
[
  {
    "q": "JWT を使っていて、ログアウトしたら即座に無効にしたい。何が必要？",
    "choices": ["サーバー側に失効リスト（またはセッション）を持つ", "有効期限を長くする", "localStorage から消せば十分"],
    "answer": 0,
    "explain": "JWT は署名だけで検証できるため、サーバーが状態を持たないと発行済みのトークンを止められない。",
    "ref": "#revoke"
  }
]
</script>
```

| キー | 必須 | 内容 |
| --- | --- | --- |
| `q` | ○ | 問題文 |
| `choices` | ○ | 選択肢 2〜5 個（表示順はトップ・クイズページではシャッフルされる） |
| `answer` | ○ | 正解の番号（0 始まり） |
| `explain` | | なぜそれが正解かを 1〜2 文 |
| `ref` | 推奨 | 本文で説明している箇所の `#id`。間違えたときに「本文で確認する」リンクになる |

### 作問のルール

- **実際に使う場面で役立つことだけを聞く。** 「どれを選ぶか」「何が起きるか」「なぜそうなるか」「どこが違うか」を、具体的な場面を添えて問う。
  - ✓「背景が写真のヘッダーで、文字を読みやすく保ちながら奥行きを出したい。合うスタイルは？」
  - ✓「`docker run` で起動したコンテナから、ホストの他のプロセスが見えないのはなぜ？」
- **雑学・暗記の問題は出さない。** 年号（流行った年・リリース年）、人名、開発元、命名の由来、バージョン番号、細かい数値など、知っていても判断や作業に使わないものは問題にしない。デザインや歴史のページでも同じ。
- 誤答の選択肢は「よくある誤解」や「似ているが別の場面向けのもの」にする。明らかに違う選択肢で数を埋めない。
- 正解の位置（`answer`）を散らす。全問 1 番目が正解、のように偏らせない（各ページのクイズは書いた順に表示される。全問同じだと lint が指摘する）。
- 正解だけ長く詳しい、のように選択肢の長さや書き方で答えがわからないようにする。
- 主なセクションごとに 1 問くらい。同じことを言い換えた問題を並べない。
- 問題文だけで意味が通るように書く（トップやクイズページでは、ページの外で 1 問だけ表示される）。「この図で」「上の表の」のような書き方はしない。
- `ref` の飛び先は、説明している見出し（`h2` など）や要素に `id` をつけて指定する。タブや `<details>` の中でも、飛ぶときに自動で開く。
- JSON の文字列に `</script>` を書かない。

## 崩れ防止（コピペ事故対策）

- CSS / JS の引用符は必ず半角 `'` `"`。全角 `‘’“”` は font-family が効かなくなる原因。
- セレクタ `*` を行頭に置くとき、Markdown 経由で `-` や `\*` に化けないよう、ファイルとして直接保存する。
- 書いたら `python3 scripts/memo.py lint NAME` で確認する。

## 会話内でプレビューするとき

クイズの表示（CSS / JS）は `docs/assets/memo-quiz.*` を参照する形なので、HTML をそのまま送るとクイズが動かない。
`preview` で中身を埋め込んだ 1 枚を作って送る（同じファイルから埋め込むだけなので、公開版と見た目・動きは変わらない）。下書きのファイルパスにも使える。

```bash
python3 scripts/memo.py lint 下書き.html --fix --backlink           # 自動生成ブロックを入れて崩れを直す
python3 scripts/memo.py preview 下書き.html -o <スクラッチパッド>/NAME.html
```

送るのは preview の出力。保存（memo-publish）するときは元の下書きを使う。

## 書き終えたら

memo-publish の手順 4 以降（lint → meta → build → commit/push → 報告）で登録する（`new` で作ったので取り込み手順 3 は不要）。
